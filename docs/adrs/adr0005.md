# ADR-0005 — Externalize Role Prompts

## Status

Accepted

## Date

2026-08-01

## Implementation status

Implemented in v1; install-safe runtime packaging amended by BTN-163.

## Context

Prompt content changes more often than node mechanics. Embedding prompts as
Python constants would couple prompt iteration to role implementation changes.

## Decision

Store default role prompts as plain-text Python package data under
`battalion/prompts/`. Resolve Battalion-owned defaults through
`importlib.resources`, not repository-root traversal, so the same explicit
runtime-resource contract works in source checkouts, installed wheels, and the
frozen desktop worker.

Node functions may accept explicit prompt or prompt-directory overrides for
tests and customization. An explicitly supplied directory is authoritative and
must not silently fall back to a packaged default when a required file is
missing, empty, or invalid. Those cases fail through the typed prompt error with
operator-actionable context.

The declared prompt-contract inventory is also the release artifact inventory.
Wheel, sdist, and frozen-worker validation must load or inspect every declared
asset without credentials or provider calls.

## Rationale

External files make prompt changes reviewable on their own and allow node code
to focus on mechanically enforced inputs, outputs, and authority.

## Consequences

- Every role requires a corresponding non-empty prompt file.
- Default prompt files are Battalion-owned runtime assets, not repository-layout
  support files.
- Missing or empty prompts fail explicitly rather than silently degrading.
- Prompt text must accurately describe the node's real context, tools, output
  contract, and authority.
- Prompts should resolve the role's immediate handoff concisely rather than
  invite repeated task restatement or narrated deliberation. This improves
  operator trace readability and avoids needless provider tokens without
  changing role authority or a mechanical output contract.
- When a node permits a structured no-op, its prompt and parser must describe
  the same explicit representation rather than asking the model for an
  explanation that the parser cannot accept.
