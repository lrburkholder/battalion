# ADR-0030 — Complete explicitly linked tickets after human PR merge

## Status

Accepted

## Date

2026-08-26

## Decision

A least-privilege GitHub Action runs only after a human merges a pull request
into `main`. It accepts exactly one authoritative ticket declaration in the PR
body, using one of these mutually exclusive full-line forms:

- Legacy single-ticket form: `Battalion-ticket: #<number>`
- Multi-ticket form: `Battalion-tickets: #<number>, #<number>[, ...]`

The plural form is the canonical contract for integration or release PRs that
complete more than one ticket. A PR must not contain both forms, more than one
declaration line, duplicate Issue numbers, an empty plural declaration, or
tokens outside the exact `#<positive-integer>` comma-separated grammar.
Ordinary Issue references, branch names, titles, commit messages, and other PR
text remain non-authoritative.

The action parses the complete declared ticket set before mutation. It then
fetches and validates every declared Issue through the ADR-0027 canonical Issue
schema. Every open Issue must have exactly `status:in-review`; a schema-valid
already-closed Issue with no active lifecycle label is an allowed reconciliation
state. If any declared Issue is malformed, schema-invalid, or in an ineligible
open lifecycle state, the action performs no Issue mutation.

Only after the entire set passes validation may mutation begin. For each open
Issue, the action removes its active lifecycle label before closing it. Mutation
order is deterministic. Because GitHub does not provide a cross-Issue
transaction, an external API failure can still interrupt a mutation sequence;
reruns therefore treat already-completed Issues as reconciliation states and
continue toward the same final result.

The action cannot approve or merge PRs. Human merge into `main` remains the
authority boundary that permits completion.

## Consequences

The canonical Issue transition remains explicit after merge while now supporting
one integration PR that delivers multiple reviewed tickets. Validation is
set-wide and happens before mutation, preventing policy errors in one declared
ticket from partially completing another. Reconciliation semantics make
external mid-sequence failures recoverable without weakening the no-inference
rule.

Pre-merge review validates the canonical Issue corpus, while Pages publishes
status through its separate rendering boundary.

## Amendment (BTN-128, 2026-08-27)

The lifecycle Action no longer regenerates or commits status Markdown. It keeps
the least-privilege lifecycle mutation boundary; public status is rendered by
the Pages publication pipeline under ADR-0031.

## Amendment (BTN-152, 2026-08-28)

The lifecycle declaration contract now supports an explicit plural marker for
multi-ticket integration and release PRs. The existing singular marker remains
a compatibility path for exactly one ticket. The two forms are mutually
exclusive, validation covers the complete declared set before any mutation, and
already-completed schema-valid Issues provide reconciliation after interrupted
GitHub mutations.
