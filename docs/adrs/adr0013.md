# ADR-0013 — Bind Write Tools to Project Layout Phases

## Status

Accepted

## Date

2026-08-13

## Implementation status

Implemented by BTN-28.
BTN-164 adds explicit Reviewer project-input materialization.
BTN-166 enforces project containment for declared authority roots.

## Context

Battalion originally used one `driver: [src/]` declaration for Driver RED,
Driver GREEN, and Refactorer. That represented projects which colocate tests
and implementation under `src/`, but it could not safely represent Battalion's
own root-level `tests/` and `battalion/` directories. Granting a writing node
the repository root would make the layout work by broadening its authority,
which conflicts with ADR-0002.

## Decision

Allow `write_scope` to declare independent `driver_red`, `driver_green`, and
`refactorer` directory roots. Each writing phase builds tools from only its own
entry. An explicitly present entry, including an empty one, is authoritative.

For migration, a missing phase-specific entry falls back to the existing
`driver` entry. The default remains `driver: [src/]`, so existing configurations
and root-relative model output continue to work unchanged. Refactorer's legacy
fallback preserves ADR-0008 for old configurations; an explicit `refactorer`
entry supersedes that shared declaration.

BTN-166 requires every configured root, including legacy and inactive phase
entries, to pass ADR-0002's project containment rule before any tools are
exposed. Directory and single-file entries use the same normalizer; a trailing
slash of either style denotes directory mode. Absolute paths, parent traversal,
drive-relative/alternate-drive and device paths, and escaping links/junctions
are configuration failures. Repository-wide grants remain forbidden for all
v1 roles. Invalid explicit entries never fall back to `driver` or `src/`.
Containment does not relax RED/GREEN suffix rules, Architect's `plan.md` output,
Reviewer's zero-write contract, or Refactorer's admitted-artifact restrictions.

Output paths remain relative to a bound root when a phase has one root. When a
phase declares multiple roots, output must name one of those roots as a prefix
so selection is unambiguous. Absolute paths, traversal, and undeclared roots
remain blocked by the bound tools before any file in a batch is written.

Reviewer receives no write tools. It verifies a clean copy of the configured
project root, rather than assuming the test runner belongs under `src/`.

BTN-164 makes that copy an explicit materialization policy: Git supplies tracked
files plus nonignored untracked candidate files; non-Git projects use a pruned
regular-file walk. Both exclude build/distribution/coverage outputs, virtual
environments, dependency directories, caches, Battalion state, and VCS metadata.
Deleted tracked files and directory links are omitted. Internal file links are
copied as regular files; links outside the project are not admitted. The selected
inputs, not the original tree's generated content, supply the Reviewer context
digest. Only Battalion's disposable scratch directory is written; Reviewer still
receives no project write tools. This copy is not an OS security sandbox.

The exclusion vocabulary is explicit in `battalion/reviewer_testing.py` rather
than being inferred from file size or a broad recursive copy. Future isolated
workspace lifecycle work may replace the mechanism without weakening the
classified evidence contract in ADR-0007 and ADR-0014.

## Rationale

Phase-specific entries express the least authority each role needs while
keeping enforcement structural. Compatibility belongs in scope selection, not
in a repository-wide tool or a CLI special case. Testing the project root lets
normal test discovery represent layouts such as `tests/` plus `battalion/`.

## Consequences

- Battalion can dogfood with RED limited to `tests/` and GREEN/Refactorer
  limited to `battalion/`.
- Driver RED, Driver GREEN, and Refactorer may intentionally have different
  implementation roots.
- Explicit phase entries should be used for new configurations; `driver` is a
  backward-compatible migration path.
- ADR-0002's structural boundary is unchanged.
- ADR-0008 remains the legacy default but no longer requires Refactorer to
  share Driver GREEN's scope when a project declares otherwise.
