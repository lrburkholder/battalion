# ADR-0023 — Persist Human Actions with Their Existing Authority

## Status

Accepted

## Date

2026-08-20

## Implementation status

BTN-43 was completed on 2026-08-20 after the human operator accepted this
decision. The offline suite passed 418 tests, and native validation confirmed
that both the split lightweight desktop and independent graph/provider worker
distributions build successfully.

## Context

RFC-0004 defines two next-attempt intervention intents: a Correction for
Driver RED, Driver GREEN, or Refactorer, and a Design decision for Architect.
It excludes Reviewer-targeted intervention, Reviewer verdict override, manual
checkpoint override, and mid-generation steering. The shipped state contract
does not yet represent a typed intervention queue or a complete durable record
of human run actions.

The existing authorities are intentionally split. `RunState` and the graph own
run progress and interrupts. `InstinctReviewWorkflow` and its append-only
decision repository own candidate promotion and rejection. ADR-0021 requires
presentation clients to use application commands for mutations and forbids a
live-observation stream from becoming graph control. BTN-43 must add desktop
controls without creating a second authority or mutable copy of Recon evidence.

An intervention also needs an unambiguous delivery point. Merely appending text
to the specification would erase its intent, target, actor, timing, and
disposition. Injecting text into an active provider request is unsupported and
would make delivery timing impossible to reconstruct.

## Decision

Keep each action with the durable authority whose state it changes and expose
all actions through typed, transport-neutral commands in
`battalion.application`.

Run actions are persisted in `RunState` as bounded, immutable values. Each
record has a stable action identifier, action kind, actor, timezone-aware
request time, exact target, disposition, and resulting durable run status,
phase, and state version. Interrupt resolution identifies one unresolved
interrupt and records its resolution before the existing resume operation may
continue through the canonical graph path.

An intervention is a typed run action with exactly one of these target pairs:

- `correction` → `driver_red`, `driver_green`, or `refactorer`
- `design-decision` → `architect`

Its text is bounded separately from the ticket specification. Submission is
authorized only while no worker is executing the run. A valid intervention is
queued for the next attempt of its exact target. At target-node entry, Battalion
durably associates it with the new node-attempt identity before assembling
context or starting provider generation. Context renders it in a named Human
intervention section and context provenance identifies the action record. Once
associated, it is not supplied to a later attempt. A crash before association
leaves it queued; a crash after association preserves which attempt received
it. Other roles, especially Reviewer, never receive the text.

Recon review remains outside `RunState`. Application commands load the immutable
candidate and delegate accept, edit-and-accept, or reject to the canonical
`InstinctReviewWorkflow`. Its append-only decision remains the human-action
record and must expose actor, time, candidate target, disposition, and resulting
accepted identifier or rejected state. The original candidate is never edited.

Desktop and CLI adapters receive typed results and domain failures. They do not
write `RunState`, decision files, accepted Intel, worker records, or graph
control state directly. Desktop long-running resume work continues through the
detached worker path selected by ADR-0019.

The standalone release preserves that process boundary mechanically. The Qt
client and graph/provider worker are built as sibling distributions. UI-only
builds continue excluding `battalion.graph`, LangGraph, and LiteLLM; the worker
entry contains execution authority and is launched through the same stdin
request contract as source-mode `python -m battalion.workers`. A missing worker
distribution is a typed launch failure, not an invitation for the UI process to
invoke graph code. Pytest is excluded from both release closures, and separate
Nuitka reports retain the evidence needed for further anti-bloat decisions.

## BTN-165 amendment — crash-consistent authorization and delivery

The BTN-165 recovery contract (2026-08-30) persists a
resume intent in the same atomic `RunState` replacement as interrupt resolution
or typed blocked-result authorization. The intent links the original action
record and remains pending until an attempt outcome is durably recorded.
Retrying a pending request uses the same actor, resolution, and action evidence;
it does not resolve the interrupt twice. Stable caller-supplied action IDs also
deduplicate completed resume and intervention requests. A reused ID with changed
evidence is rejected, and a completed action cannot authorize a later interrupt.

Register the unfinished execution and intervention association together before
context assembly. A separate pre-execution checkpoint marks the attempt started.
Only an unstarted attempt may reuse the receiving identity on recovery. Preserve
the original prompt/model configuration and one-attempt context authority.
An already delivered intervention never moves to an automatic correction or a
later attempt. Persist correction context and the consumed correction allowance
so restarting cannot grant extra automatic retries.

Save completed node evidence and its concrete successor before completion
observations or the next graph node. Mark graph outcome checkpointing separately.
Recursion limits retain the latest checkpoint and any existing typed block's
phase and human-resolution requirement, even before its terminal graph node
executes. Application error handling
reloads saved evidence without writing the old input. CLI and desktop use the
same typed recovery assessment. An attempt that started without a saved outcome
has potentially unknown file/provider effects: automatic replay is terminally
refused. The operator must inspect the workspace and record before starting a
new run. This conservative boundary preserves human authority without claiming
exactly-once execution or adding rollback authority.

Existing role definitions, scope enforcement, and interrupt taxonomy do not
change. This amends the persistence ordering and recovery guarantees rather
than adding a seventh interrupt or a second state store.

BTN-173's integration correction preserves pending correction context and its
consumed retry allowance when authorizing a budget pause. Recovery cannot turn
that authorization into an extra automatic retry or skip a typed block's own
human decision.

## Consequences

- Human action evidence stays co-located with the canonical state it changes;
  no parallel event store or UI-owned queue is introduced.
- A presentation restart can reconstruct queued, delivered, accepted, rejected,
  and failed outcomes from durable repositories.
- Intervention delivery requires a pre-generation durable checkpoint tied to a
  node-attempt identity. This is a graph change and needs failure-path tests.
- Existing run files remain readable because the new collections default to
  empty. Older unresolved interrupts require an explicit resolution before a
  BTN-43-aware client resumes them.
- Candidate review can reuse the audited workflow, but application-level error
  translation and result types are still required.
- Cancellation remains worker supervision, not an intervention disposition.
- Presentation-only changes no longer require recompiling the provider runtime;
  release assembly must ship both sibling distributions.

## Alternatives rejected

### Store all actions in a new project event log

This would duplicate run and Intel authority and create ordering and recovery
questions that ADR-0021 deliberately avoided.

### Append intervention text to the ticket specification

This loses intent and delivery state, can leak a Correction to Architect or
Reviewer, and makes one-attempt consumption unverifiable.

### Let the desktop call graph or Intel repositories directly

This would create a presentation-specific control path and violate ADR-0022's
thin-adapter boundary.

### Deliver intervention text to an in-flight model call

The current provider and node contracts have no safe mid-generation steering
channel. Claiming otherwise would make the UI promise behavior the runtime does
not provide.
