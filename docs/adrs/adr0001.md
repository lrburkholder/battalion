# ADR-0001 — Use Pydantic for State Validation

## Status

Accepted

## Date

2026-08-01

## Implementation status

Implemented in v1.

## Context

Battalion needs one versioned state contract that can be validated at every
persistence and graph boundary. Maintaining JSON Schema separately from Python
types would create two representations that could drift.

## Decision

Define the shared state contract as Pydantic models rather than as JSON Schema
plus dataclasses.

## Rationale

Validation and Python types live in one place, and state objects pass naturally
through LangGraph nodes without a separate validate-then-cast step.

## Consequences

- Pydantic is a core dependency across the graph.
- State schema changes must preserve explicit versioning and migration concerns.
- Persistence boundaries can reject malformed state before it reaches role code.
