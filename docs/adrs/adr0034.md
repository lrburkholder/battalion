# ADR-0034 — Keep Tactician advisory and outside Implementation Runs

**Status:** Accepted  
**Date:** 2026-08-29  
**Implements:** BTN-140  
**Related:** RFC-0012, ADR-0003, ADR-0032, ADR-0033

## Context

RFC-0012 assigns Tactician a narrow semantic-assessment role when bounded,
deterministic workflow admission remains uncertain. It must add inspectable
advice without becoming a workflow authority, an Architect substitute, or a
hidden precondition for all work.

## Decision

Tactician accepts a revision-pinned deterministic `UNCERTAIN` assessment,
bounded supplied evidence, known scope, exact registered-recipe summaries,
mandatory policy references, and explicit human constraints. It emits a
versioned `TacticianAssessment` containing either an exact supplied registered
recipe recommendation or clarification, concise rationale, risk flags, missing
evidence, input evidence references, and model/prompt/non-secret configuration
provenance with sourced token/cost evidence.

The shared application boundary resolves the `tactician` model through normal
Battalion configuration (falling back to `default`); Tactician cannot choose a
model, change a registry, authorize a recipe, construct a graph, or persist a
Run. It is rejected before model invocation for deterministic full-required or
compact-admissible admission. Malformed output and normal provider failures
yield no assessment and therefore cannot authorize compact execution. Raw
provider reasoning is neither retained nor part of the durable contract.

## Consequences

Tactician is pre-admission evidence, not a LangGraph node or `RunState` field.
BTN-141 retains human admission authority, BTN-142 owns compact execution and
upgrade policy, and BTN-143 owns persistence and resume references. The role's
bounded rationale can make human/Tactician disagreement inspectable without
promoting model inference into policy or architecture authority.
