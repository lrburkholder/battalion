# ADR-0011 — Establish an Engineering Knowledge System

## Status

Proposed

## Date

2026-08-05

## Implementation status

Future-facing; not part of the shipped v1 graph.

## Numbering note

This decision was originally recorded as ADR-0008. It was renumbered because
ADR-0008 was already assigned to Refactorer's write scope in the v1
architecture plan.

## Context

Engineering sessions produce observations that can improve future work, but
capturing, accepting, storing, retrieving, and evaluating that knowledge are
different responsibilities. Combining them would obscure human authority over
institutional knowledge.

## Decision

Use four separate responsibilities for the Engineering Knowledge System:

- Recon produces candidate instincts from completed executions.
- Intel Repository stores immutable, human-accepted instincts.
- Intel selects relevant instincts for future node executions.
- Operator Feedback records usefulness evidence that informs retrieval
  confidence.

Recon is Battalion's canonical name for knowledge capture. "Learner" refers
only to the historical Regiment process.

## Rationale

Separation preserves single responsibility, keeps acceptance under human
control, and allows capture, persistence, retrieval, and evaluation to evolve
independently.

## Consequences

- The knowledge system requires additional persistence and indexing.
- Prompt context can remain focused through role-specific retrieval.
- Automatic standards generation, cross-project sharing, and semantic or
  embedding-based retrieval remain deferred.
