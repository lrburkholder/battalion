# ADR-0032 — Register finite, versioned WorkflowRecipe policy artifacts

**Status:** Accepted  
**Date:** 2026-08-28  
**Implements:** BTN-138  
**Related:** RFC-0012, ADR-0003, ADR-0014

## Context

RFC-0012 requires workflow admission to select an explicit, proportionate
workflow without granting a model authority to invent a graph. A persisted or
historical Run must remain interpretable against the exact workflow semantics
under which it was admitted.

## Decision

Battalion owns a finite registry of immutable `WorkflowRecipe` policy artifacts.
Each recipe has a stable `recipe_id` and `recipe_version`, a workflow kind,
ordered semantic stages, capabilities, required verification, independent-review
requirement, and references to interrupt, eligibility, and upgrade policy.

The registry resolves an exact `(recipe_id, recipe_version)` only. It never
chooses a later version for an older reference, rejects duplicate and unknown
keys, and rejects unversioned lookup when multiple historical versions exist.
A changed recipe therefore receives a new version; old definitions remain
available for historical interpretation.

The default registered recipe represents the existing full Implementation Run
and retains its current RED/GREEN verification, independent review, scoped
writes, authorization, side-effect, provenance, cost, and interrupt assurance.

Recipes are Battalion/project policy artifacts. Tactician and other model output
cannot submit recipe definitions or arbitrary LangGraph node lists. The shared
application boundary exposes read-only recipe enumeration and exact inspection;
it does not expose graph construction or persistence.

## Consequences

BTN-138 creates the vocabulary and lookup boundary only. Admission selection,
compact execution, Run persistence of the selected identity, resume behavior,
and graph dispatch remain owned by BTN-139 through BTN-144. This preserves the
v1 graph until an admitted recipe is explicitly integrated through those tickets.
