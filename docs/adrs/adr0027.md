# ADR-0027: Generate status documentation from canonical GitHub Issues and Milestones

Date: 2026-08-23
Status: Accepted, amended by BTN-102 on 2026-08-26 and BTN-104 on 2026-08-27

## Context

Ticket status was hand-maintained in four places: README Status and Roadmap
sections, `plan.md`, the ADR index, and the original repository backlog. The
copies had already drifted. GitHub-flavored Markdown also has no include or
transclusion mechanism, so a single source document cannot be composed when
rendering the README.

The original accepted decision used `backlog.json` as the initial
machine-readable ticket authority and explicitly anticipated an input swap
once the GitHub-backed path was ready. That migration is now complete: retaining
the file as a synchronized compatibility database would create the same
dual-authority problem this decision was meant to solve.

## Decision

- GitHub Issues are the sole canonical source for Battalion ticket identity,
  scope, dependencies, lifecycle status, and Issue Schema v1 metadata.
- The locked Issue Schema v1 metadata (`ticket_id`, phase, priority, and
  assignee role) must agree with classification labels. `unknown` priority or
  role has no corresponding label. The phase vocabulary includes `design`; no
  `role:specifier` vocabulary is admitted.
- `scripts/sync_status.py` has a narrow GitHub CLI retrieval boundary, then
  validates and normalizes Issue data before pure deterministic rendering.
  Unit tests inject fixed Issue fixtures and therefore require neither a token
  nor network access.
- GitHub lifecycle mapping is explicit: an open Issue without a `status:*`
  label is not-started; the three active labels map to in-progress, blocked,
  and in-review; completed and not-planned closed Issues map to done and
  cancelled. Unsupported combinations fail rather than being reinterpreted.
- `docs/status.md` remains the human-readable status document. Its generated
  Delivered work region is spliced verbatim into `README.md`; `--check` fails
  when either projection drifts from the authenticated GitHub Issue set.
- CI grants the status check only read access to Issues through its GitHub
  token. `backlog.json` is retired, is not published to Pages, and no active
  code path treats it as current ticket truth.

## Consequences

- A ticket status change is made once on its canonical Issue, then appears in
  bounded generated README/status diffs after synchronization.
- Schema or label drift is visible before rendering; normalization never
  invents missing classification data or silently chooses between conflicts.
- The checked-in projections remain reviewable Markdown and Pages content,
  while normal unit tests remain deterministic and credential-free.
- GitHub availability is required only for synchronization and CI drift
  verification, not for the renderer or its unit tests.

## Future

The initial GitHub CLI reader is intentionally replaceable. BTN-72 and BTN-96
may later supply the production GitHub Issues `WorkSource` behind the same
retrieval boundary without changing Issue normalization, rendering, embedding,
or source authority (RFC-0006 / ADR-0025).

## Amendment (BTN-128, 2026-08-27)

ADR-0031 supersedes the checked-in projection and README embedding portions of
this decision. GitHub Issues and Milestones remain canonical, and deterministic
normalization remains separately tested. Ordinary CI now validates the live
canonical corpus without asserting that a branch snapshot matches it; Pages
renders the one public status projection from current canonical data.

## Amendment (BTN-104, 2026-08-27)

The public projection retrieves canonical GitHub Issues and the complete
canonical GitHub Milestone collection. Issue membership supplies milestone
counts; milestone records supply lifecycle state and retain milestones with no
Issues. Battalion milestone titles sort by their `BTN-M#` number, not GitHub
creation order or opaque IDs. Completed counts exclude `NOT_PLANNED` Issues,
which remain visible as cancelled rather than becoming completed work.

If either canonical collection cannot be retrieved, status generation fails
with an explicit unavailable-GitHub error. It never falls back to a
checked-in document or `backlog.json`. Deterministic tests inject both
collections, leaving ordinary test CI credential- and network-independent.
