# ADR-0006 — Split Driver Into RED and GREEN Modes

## Status

Accepted

## Date

2026-08-01

## Implementation status

Implemented in v1 by BTN-11.

## Context

The original Driver produced tests and implementation in one call. That made it
impossible for Reviewer to verify a genuine failing-test checkpoint before the
implementation existed.

## Decision

Give Driver explicit `red` and `green` modes. RED produces failing tests; GREEN
produces the smallest implementation against accepted tests. Both modes retain
the same file-output shape.

## Rationale

Separate calls create independently reviewable checkpoints and preserve the
RED-before-GREEN development invariant.

## Consequences

- Graph routing must distinguish Driver's RED and GREEN phases.
- Reviewer must evaluate each phase against a different expected outcome.
- Mode changes requested work, not extraction or scoped-write mechanics.
