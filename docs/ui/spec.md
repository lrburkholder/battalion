# Purpose

This specification defines the first user interface for Battalion.

Rather than attempting to expose every future capability, this version focuses on
the central experience of executing, inspecting, and understanding Battalion
agent runs.

The UI should prioritize transparency, provenance, and engineering workflow over
traditional chat interfaces.

---

# Scope

Included

- Runs hub
- Current run
- Historical runs
- Run inspection
- Execution graph
- Token usage
- Cost reporting

- Provenance
- Navigation shell

Explicitly Out of Scope

- Multi-project support
- Search
- Knowledge graph
- Memory management
- Settings
- Plugin ecosystem
- Team collaboration
- Authentication

The architecture should make future expansion straightforward.

# Design Principles

## Project before Conversation

Battalion is an engineering system, not a chat application.

Conversation is one artifact among many.

The UI should present engineering work rather than conversational history.

---

## Transparency over Magic

Every AI decision should be inspectable.

Users should be able to determine

- why something happened
- what model was used
- what context was supplied
- what tools were invoked
- what artifacts were produced

---

## Provenance by Default

Every durable artifact should expose its origin.

Example

ADR-18

Generated by

Architect Run #184

based on

Spec v2

Research Session #71

---

## Progressive Disclosure

The default interface should remain calm.

Detailed execution traces should appear only when requested.

---

## History is a First-Class Feature

Runs are permanent engineering artifacts.

Users should be encouraged to revisit previous work.

---

## Observability is Built In

Every execution records

- duration
- latency
- model
- provider
- token usage
- cost
- tool usage
- generated artifacts

# Non-Goals

Version 0.1 is not intended to become

an IDE

a replacement Git client

a replacement terminal

a generic chat application

The UI exists to expose Battalion's execution model.

---

# Acceptance Criteria

A user can

observe Battalion executing

inspect any completed run

understand why a run occurred

inspect every generated artifact

see token usage

see cost

see model selection

navigate previous runs

trace artifacts back to their source

without reading implementation logs.
