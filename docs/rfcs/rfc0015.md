## Decision record

RFC-0015 is accepted with the design choices established during architecture review. The normative architecture is the version immediately preceding this acceptance commit (`17cc08167175a2ae0ead4301abc53c6d62acd2bf`), including its full rationale, alternatives, migration strategy, testing requirements, and resolved design choices.

The accepted invariants are:

1. **Workflow boundaries are explicit, typed, versioned, and Battalion-owned.**
2. **Canonical artifacts are separate from bounded model-context projections.**
3. **RunState remains orchestration/checkpoint state, not the universal semantic handoff payload.**
4. **Receiving inputs are assembled by Battalion from authoritative artifacts/evidence, not blindly forwarded from producer state.**
5. **Downstream artifacts preserve explicit references to governing authority; specificity does not silently supersede upstream authority.**
6. **Required unresolved/missing/incompatible governing artifacts fail boundary admission explicitly.**
7. **Pre-execution plan/task consistency is represented by structured evidence of the relationships actually checked and is produced by a reusable Battalion capability.**
8. **Contract version compatibility and adapters are explicit and auditable; breaking or undeclared data is never silently coerced merely because it parses.**
9. **Initial Python contract authoring uses Pydantic while durable protocol identity and portable schema representation remain implementation-independent.**
10. **Provider/plugin payloads are normalized before becoming workflow data.**
11. **Human authority-bearing decisions remain separate durable records.**
12. **Artifact storage is hybrid: project knowledge remains portable while Battalion operational intelligence remains independently durable.**
13. **The mechanism supports both intra-Run stage boundaries and cross-Run artifact flow without creating a second source of truth.**

### Resolved design choices

- **Canonical artifact storage:** hybrid. Battalion persistence owns operational intelligence and execution evidence; project-facing authority artifacts may live in repositories or other authoritative stores and remain exportable.
- **Contract schemas:** Pydantic-first authoring and validation with a language-neutral durable representation such as generated JSON Schema. Durable protocol identity does not depend on Python import paths.
- **Inline versus referenced values:** independently meaningful, revisable, authoritative, reusable, inspectable, or exportable values are canonical referenced artifacts; small bounded control values may remain inline.
- **Preflight consistency:** a reusable Battalion-owned capability, invokable during Architecture Run review and again at implementation admission when evidence is missing, stale, incomplete, or tied to different revisions.
- **Compatibility:** consumers explicitly declare accepted version ranges; Battalion's registry owns compatibility relationships and deterministic adapters. Successful parsing alone never establishes protocol compatibility.

### Implementation consequence

BTN-108 should now be decomposed into implementation tickets rather than implementing the entire mechanism directly in this architecture ticket. Those tickets should preserve the migration sequence established by the accepted RFC: contract primitives and artifact references first; an Architecture/plan → Driver pilot second; remaining implementation/review boundaries and reusable preflight integration next; obsolete universal-state coupling removed only after typed consumers are in place.
