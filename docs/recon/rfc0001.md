# RFC-0001 — Recon Node

**Status:** Draft
**Author:** Architecture
**Target Release:** M1
**Related:** `philosophy.md`, ADR-0008

---

# Summary

Introduce a terminal execution node responsible for converting engineering experience
from a completed Battalion execution into reusable engineering knowledge.

Recon never affects the current execution.

Instead, it produces candidate Instinct documents that may later be accepted,
edited, or rejected by the human operator.

---

# Motivation

Every execution produces observations.

Most are forgotten.

Some become permanent engineering knowledge.

Battalion should assist in capturing these observations while leaving the human
responsible for deciding what becomes institutional knowledge.

---

# Responsibilities

Recon SHALL:

- inspect the completed execution
- inspect reviewer findings
- inspect test failures and resolutions
- inspect architectural decisions made during execution
- identify reusable engineering lessons
- generate zero or more candidate Instinct documents

Recon SHALL NOT:

- modify repository standards
- modify ADRs
- modify specifications
- rewrite backlog items
- influence the execution that generated the observations

---

# Inputs

- Final Battalion state
- Node outputs
- Conversation history
- Review output
- Human interventions
- Test results

---

# Outputs

Zero or more Instinct markdown documents.

Each document shall contain:

- metadata
- recommendation
- supporting evidence

---

# Success Criteria

A successful Recon execution produces instincts that are:

- narrowly scoped
- evidence-backed
- independently understandable
- useful in future executions
- non-duplicative

Producing zero instincts is a valid outcome.

---

# Deferred Work

Out of scope:

- instinct promotion
- confidence evolution
- instinct merging
- cross-project sharing
- automatic standards generation
